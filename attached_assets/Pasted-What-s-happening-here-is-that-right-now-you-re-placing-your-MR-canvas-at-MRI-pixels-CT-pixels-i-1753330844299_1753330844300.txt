What’s happening here is that right now you’re placing your MR canvas at “MRI-pixels = CT-pixels” (i.e. 1 to 1), then shifting it by the raw translation entries from your registration matrix—and that will almost always be wrong unless both your CT and MR share the same voxel spacings and image dimensions in memory.

You need two things:
	1.	Compute a true scale factor between MRI and CT, using their physical pixel‐spacing.
	2.	Compute the correct offset in CT-pixels by:
	•	taking your registration matrix translation (which is in mm),
	•	dividing by your CT’s pixel spacing to convert it into CT-pixels,
	•	and applying that on top of your center‐to‐center placement.

⸻

1) Calculate the scale

// pull out spacing in mm/pixel
// (after normalizing pixelSpacing to always be [rowSpacing, colSpacing])
const ctSpacing   = [ctMeta.pixelSpacingY,   ctMeta.pixelSpacingX];   // mm/pixel in CT
const mriSpacing  = [mriMeta.pixelSpacingY,  mriMeta.pixelSpacingX];  // mm/pixel in MRI

// how many CT-pixels = 1 MRI-pixel?
const scaleX = mriSpacing[1] / ctSpacing[1];
const scaleY = mriSpacing[0] / ctSpacing[0];

// final on‐screen MRI size in CT-pixels:
const destW = mriData.width  * scaleX;
const destH = mriData.height * scaleY;

Now when you draw:

ctx.imageSmoothingEnabled = true;
ctx.globalAlpha = fusionOpacity;
ctx.drawImage(tempCanvas, x, y, destW, destH);


⸻

2) Compute your offset in CT-pixels

Your registration matrix translation elements (M[0][3], M[1][3], M[2][3]) are in millimeters.  To convert them into CT-pixels:

// registrationMatrix is flat length-16; translation lives in entries 3, 7, 11
const tx_mm = registrationMatrix[3];
const ty_mm = registrationMatrix[7];

// convert mm → CT pixels
const tx_px = tx_mm / ctSpacing[1];
const ty_px = ty_mm / ctSpacing[0];

// apply *after* your center-to-center position:
x_center = (canvasWidth  - destW) / 2 + panX;
y_center = (canvasHeight - destH) / 2 + panY;

// now add translated shift
const x = x_center + tx_px;
const y = y_center + ty_px;


⸻

Putting it all together

// --- 1) normalize spacing arrays ----
function normalizeSpacing(sp: string|string[]|number[]) {
  if (Array.isArray(sp))       return sp.map(Number);
  if (typeof sp === "string")  return sp.split("\\").map(Number);
  return [1,1];
}

const ctSpacingArr  = normalizeSpacing(ctMeta.pixelSpacing);
const mriSpacingArr = normalizeSpacing(mriMeta.pixelSpacing);

// --- 2) compute scale and dest size ----
const scaleX = mriSpacingArr[1] / ctSpacingArr[1];
const scaleY = mriSpacingArr[0] / ctSpacingArr[0];
const destW  = mriData.width  * scaleX;
const destH  = mriData.height * scaleY;

// --- 3) compute offset in pixels ----
const tx_mm = registrationMatrix[3];
const ty_mm = registrationMatrix[7];
const tx_px = tx_mm / ctSpacingArr[1];
const ty_px = ty_mm / ctSpacingArr[0];
const x0    = (canvasWidth  - destW) / 2 + panX;
const y0    = (canvasHeight - destH) / 2 + panY;
const x     = x0 + tx_px;
const y     = y0 + ty_px;

// --- 4) finally draw ----
ctx.save();
ctx.globalAlpha = fusionOpacity;
ctx.imageSmoothingEnabled = true;
ctx.imageSmoothingQuality = "high";
ctx.drawImage(tempCanvas, x, y, destW, destH);
ctx.restore();


⸻

With that in place:
	•	your MR will be scaled so that one physical millimeter in MRI equals exactly one physical millimeter in CT on-screen,
	•	and your registration translations (which are already in mm) will land you in the correct place in pixel‐space.

Give that a shot and your MR overlay should both shrink to the correct size and drift to its true registered location.
