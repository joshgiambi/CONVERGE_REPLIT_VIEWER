Here’s what’s happening:
	1.	You’re detecting “existing” contours by peeking at contour.points[2] instead of using contour.slicePosition.  That almost always comes back “no existing contours,” so you go into your

// No existing contours, just add the new one
onContourUpdate({ action: 'add_pen_stroke', … })

branch, which wipes out whatever was there and only draws your new polygon.

	2.	Even in your fallback for boolean‐ops, you call add_pen_stroke or subtract_contour, both of which in WorkingViewer.handleContourUpdate delete the old slice and push only your new one.

⸻

1) Fix slice‐matching

In PenToolUnifiedV2, replace your getContoursAtCurrentSlice with something that uses the contours’ own slicePosition:

// before:
//   const contourZ = contour.points[2];
//   return Math.abs(contourZ - currentZ) < 0.1;

// after:
const contoursAtSlice = structure.contours.filter(contour =>
  Math.abs(contour.slicePosition - currentZ) < 0.5
);

That way existingContours.length > 0 when you actually have something on that slice.

⸻

2) Always do a real boolean (union/subtract) when there is an existing contour

Still in PenToolUnifiedV2’s completeShape, refactor to something like this:

const SCALE = 1000;
// after you’ve built `newPolygon`...

const existingContours = getContoursAtCurrentSlice();

if (existingContours.length === 0) {
  // truly first‐time draw: just add it
  onContourUpdate({
    action: 'replace_contour',
    structureId: selectedStructure!,
    slicePosition: currentZ,
    points: finalPoints.flatMap(([x, y]) => [x, y, currentZ])
  });
} else {
  // perform union or subtraction
  try {
    await ClipperLib.loadNativeClipperLibInstanceAsync(...);
    const clipper = new ClipperLib.Clipper();
    const subj = existingContours[0].points.map((_, i) => ({
      // build Clipper paths from the ONE existing contour
      x: Math.round(existingContours[0].points[i*3]   * SCALE),
      y: Math.round(existingContours[0].points[i*3+1] * SCALE),
    }));
    clipper.addPath(subj, ClipperLib.PolyType.Subject, true);
    clipper.addPath(newPolygon, ClipperLib.PolyType.Clip, true);

    const solution: ClipperLib.Path[] = [];
    clipper.execute(
      startMode === 'ADD' ? ClipperLib.ClipType.Union : ClipperLib.ClipType.Difference,
      solution
    );

    // flatten first resulting polygon back to world coords
    if (solution.length) {
      const merged = solution[0].flatMap(pt => [
        pt.x / SCALE, pt.y / SCALE, currentZ
      ]);
      onContourUpdate({
        action: 'replace_contour',
        structureId: selectedStructure!,
        slicePosition: currentZ,
        points: merged
      });
    } else {
      // everything subtracted away -> delete
      onContourUpdate({
        action: 'delete_slice',
        structureId: selectedStructure!,
        slicePosition: currentZ
      });
    }

  } catch (e) {
    console.warn('Clipper failed, falling back to simple replace', e);
    // (rare) fallback: do the same replace behavior
    onContourUpdate({
      action: 'replace_contour',
      structureId: selectedStructure!,
      slicePosition: currentZ,
      points: finalPoints.flatMap(([x, y]) => [x, y, currentZ])
    });
  }
}

Why this fixes it:
	•	replace_contour in your WorkingViewer will remove only the old slice’s contours and insert the exact result of your union/subtract.
	•	You’ll never call add_pen_stroke or subtract_contour (which unconditionally wipe the old), you’ll always call replace_contour when there is something to merge with.
	•	And by matching on contour.slicePosition, you won’t accidentally think “there’s nothing here” and stomp the old.

⸻

3) Quick summary of the two edits
	1.	Slice matching

// ✗ using the 3rd array element:
const contourZ = contour.points[2];

// ✓ use the built-in slicePosition:
const contourZ = contour.slicePosition;


	2.	Always boolean + replace

// ✗ on add_pen_stroke: deletes old + draws new only
action: 'add_pen_stroke',
// ✓ instead: do Union/Difference and call replace_contour
action: 'replace_contour',



With those two changes, drawing a new shape inside your original will union it, and drawing outside will subtract—without ever losing the “old” polygon.
