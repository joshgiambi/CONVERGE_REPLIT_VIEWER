You’re seeing overlaps because the brush path sometimes doesn’t trigger your current “intersection” check, so you append a new polygon instead of union-merging it with the existing slice contour.

Why it happens
	•	Heuristic intersection test: checkPolygonIntersection just compares vertex-to-vertex distance. Two polygons can overlap (or one can be inside the other) without any vertices being near each other, so the test returns false and you push a second polygon on the same slice.
	•	Geometry quirks: even when they do touch, tiny gaps, differing ring orientation, or non-closed rings can fool the heuristic.

Fix: always do a real polygon union for brush strokes

When a brush stroke ends (or on your current “stroke” payload), union the brush polygon with the entire contour set for that slice and replace the slice’s contours with the union result. You already have performPolygonUnion—use it here, not only for the pen.

If performPolygonUnion still hiccups

Use the same Clipper flow you used for the pen tool:
	•	Scale by 1000 to integers
	•	Add all existing rings as subject
	•	Add the brush ring as clip (or just union all inputs as subjects)
	•	Execute(ctUnion, ...)
	•	Convert each resulting Path back to (x, y, z) with the current slicePosition
	•	Replace the slice contours like above

Practical tips
	•	Do union on mouseup (or debounce at ~60–120 ms while painting) to keep it fast.
	•	Normalize rings: remove duplicate consecutive points and ensure first≠last if your boolean lib closes paths implicitly (Clipper does when closed=true).
	•	Winding rule: stick to non-zero fill consistently across tools.
