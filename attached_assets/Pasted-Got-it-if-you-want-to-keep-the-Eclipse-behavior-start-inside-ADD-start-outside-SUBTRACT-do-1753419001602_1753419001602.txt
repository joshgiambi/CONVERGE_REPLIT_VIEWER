Got it—if you want to keep the Eclipse behavior (“start inside → ADD, start outside → SUBTRACT”), don’t flip your modes. The real issue is making sure Clipper sees your paths correctly (and uses the right fill‐rule). Here’s an updated completeShape() that:
	1.	Keeps your inside/outside → ADD/SUBTRACT mapping
	2.	Adds both loops as “Subject” for a union
	3.	Uses explicit EvenOdd fill rules
	4.	Properly closes and scales paths

const completeShape = useCallback(async () => {
  if (points.length < 3 || !startMode) return;

  const SCALE = 1000;
  // 1) build the new poly in Clipper coords
  const newPoly: ClipperLib.Path = points.map(([x,y])=>({
    X: Math.round(x * SCALE),
    Y: Math.round(y * SCALE)
  }));

  // 2) grab all existing loops on this slice
  const existing: ClipperLib.Path[] = getContoursAtCurrentSlice().map(c=>{
    const path: ClipperLib.Path = [];
    for (let i=0; i<c.points.length; i+=3){
      path.push({
        X: Math.round(c.points[i+0] * SCALE),
        Y: Math.round(c.points[i+1] * SCALE)
      });
    }
    return path;
  });

  await ClipperLib.loadNativeClipperLibInstanceAsync(
    ClipperLib.NativeClipperLibRequestedFormat.WasmWithAsmJsFallback
  );

  const clipper  = new ClipperLib.Clipper();
  const solution: ClipperLib.Paths = [];

  if (startMode === "ADD") {
    // union: both paths as Subject
    clipper.addPaths(existing, ClipperLib.PolyType.Subject, true);
    clipper.addPath (newPoly,   ClipperLib.PolyType.Subject, true);
    clipper.execute(
      ClipperLib.ClipType.Union,
      solution,
      ClipperLib.PolyFillType.EvenOdd,
      ClipperLib.PolyFillType.EvenOdd
    );
  } else {
    // subtract: existing=Subject, new=Clip
    clipper.addPaths(existing, ClipperLib.PolyType.Subject, true);
    clipper.addPath (newPoly,   ClipperLib.PolyType.Clip,    true);
    clipper.execute(
      ClipperLib.ClipType.Difference,
      solution,
      ClipperLib.PolyFillType.EvenOdd,
      ClipperLib.PolyFillType.EvenOdd
    );
  }

  if (solution.length === 0) {
    // nothing left → delete the slice
    onContourUpdate({
      action:        "delete_slice",
      structureId:   selectedStructure,
      slicePosition: currentZ
    });
    setPoints([]);
    return;
  }

  // 3) flatten all result paths back to world coords
  const merged = solution.flatMap(path =>
    path.flatMap(pt => [pt.X / SCALE, pt.Y / SCALE, currentZ])
  );

  onContourUpdate({
    action:        "replace_contour",
    structureId:   selectedStructure,
    points:        merged,
    slicePosition: currentZ
  });

  setPoints([]);
  setStartMode(null);
}, [points, startMode, getContoursAtCurrentSlice, selectedStructure, currentZ, onContourUpdate]);

Why this works:
	•	Union: by adding both existing loops and your new stroke as PolyType.Subject, Clipper knows to merge them rather than treat your stroke as a “clip” that deletes everything.
	•	Subtract: by putting your new stroke in the Clip slot and the old loops in Subject, Clipper only cuts out that shape.
	•	Even-Odd fill rule ensures overlapping edges don’t cancel themselves out under the default winding rule.
	•	We still respect your Eclipse-style mode: starting inside → ADD, outside → SUBTRACT.

Give that a spin—your old contour will stay intact on ADD, and only the region you draw will vanish on SUBTRACT.
